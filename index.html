01Work

Stripe Software Engineer Intern, Core Infrastructure Summer 2026 · back in Spring 2027

I was on the team that runs Stripe's service mesh, the layer every request between internal services passes through. Its load balancer had no idea how busy a backend was, so it kept sending traffic to servers that were already struggling. I rebuilt it around power-of-two-choices, so it picks two backends at random and sends the request to whichever is less loaded, based on the CPU and queue depth each one reports. Overload errors fell 40% across 50 services that handle over 400M requests a day, and with load spread evenly, teams could drop the spare replicas they had been keeping as headroom, which saved about $200K a year.

The second piece was saturation routing. A backend that's full turns requests away early so the mesh can retry them somewhere else, and when a whole zone runs hot, traffic spills over to the next one. Together they cut p99 latency 23%, and both rolled out behind feature flags in small canary stages with no incidents.

02Projects

Herd

Go · Envoy · gRPC · Kubernetes · Prometheus

A gateway that sits in front of a pool of self-hosted LLM servers and speaks the OpenAI API. I built it to see how the Stripe approach holds up when request cost varies wildly and a server that has already cached a prompt can answer it much faster. Herd sends each request to a replica that already has the prompt's prefix cached, unless that replica is overloaded, in which case it picks the one with the most free KV-cache. When everything is busy it drops low-priority requests first, keeps one tenant from starving the others, and can overflow to a cloud provider up to a set budget. It runs as an Envoy external processor, so it fits into an existing mesh.

On an 8-replica benchmark it cut p99 time to first token 55% compared to round-robin. With two replicas deliberately slowed down, round-robin's p99 time to first token climbed to 292 seconds while Herd's stayed at 12.6.

Concertify

Go · Python · PyTorch · Node.js · Redis

Finds concerts near you and ranks them by how much you actually listen to each artist on Spotify. Shows come from Ticketmaster through a Node API, a Go service scores them on artist and genre overlap, and a last pass mixes genres so the top of the list isn't ten versions of the same thing. Thumbs up and down retrain a small PyTorch model that adjusts the ranking for each person. More than 500 people have used it.

The hard part was Ticketmaster's limit of 5 requests a second, which made the first load take 9 seconds. I got it down to 2.5 seconds with a Redis cache that collapses duplicate requests, a rate limiter that spends the request budget on what's on screen first, and background warming for each profile.

Volumetric Cloud Renderer

C++ · OpenGL · GLSL

Real-time volumetric clouds. The renderer marches rays through 3D noise generated on the GPU and lights it with an approximation of multiple scattering, which is what gives real clouds their soft, bright edges. To stay fast it draws the clouds at half resolution and reuses the previous frame to fill in the rest, which makes it about 3.5× cheaper with no visible difference once the image settles.

I made it to learn real-time graphics. It also runs on a software renderer, so the screenshots here and the CI tests come from an ordinary server with no GPU.
